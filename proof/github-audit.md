# GitHub audit checklist

Run this per project before sharing a repository with a recruiter or referencing it in outreach. Complete every row with a URL, date, and observed result. Blank means not checked.

| Check | Required observation | Result / evidence |
|---|---|---|
| Repository identity | Correct project name, owner, and public URL | |
| Landing page | Clear problem, architecture, setup or demo path | |
| README claims | Metrics, maturity, and screenshots match approved/public evidence | |
| Run path | A new reviewer can identify prerequisites and a minimal local/demo path | |
| Secrets | No tokens, credentials, private URLs, or personal data in tracked files | |
| License | License status is explicit or intentionally absent | |
| Dependencies | Install and run instructions identify major dependencies and versions where relevant | |
| Tests / evaluation | Existing tests or evaluation method are described without overstating coverage | |
| Links | Demo, docs, issue tracker, and related links resolve | |
| Recruiter scan | Top-level files make the engineering contribution visible in under one minute | |

## Completion

Mark a repository `shareable` only when every applicable check has a dated observation and no unresolved secrets or broken public links remain. Otherwise share no repository link and state the limitation truthfully.
