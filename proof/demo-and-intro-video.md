# Demo and 60-second introduction checklist

## Project demo

Use a project demo only after recording the following facts:

| Item | Record before sharing |
|---|---|
| Project | One exact project name and its evidence source |
| Audience | Role/JD connection |
| URL | Public, stable link or `Not Verified` |
| Path | The 2–3 actions a viewer can take to see the behavior |
| Boundary | Data, access, maturity, or feature limitation |
| Checked | Date and device/browser used |

The demo must show an actual product path. A mockup, local recording, or planned deployment is labeled by what it is.

## 60-second introduction video

Use this evidence-first structure:

1. **0–10 seconds:** name, target role family, and one truthful engineering identity.
2. **10–35 seconds:** one project, one problem, one concrete engineering decision.
3. **35–50 seconds:** one outcome or learning, qualified exactly as the approved evidence supports it.
4. **50–60 seconds:** what role problem the work prepares Onkar to solve, without claiming company-specific knowledge.

Before sharing, check audio, captions if present, a stable link, no private data, and that every stated fact maps to the approved evidence catalogue. Record the URL and review date below.
