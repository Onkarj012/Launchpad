# Interview Loop

Build an interview-ready answer bank and practice loop without inventing project facts. It supports active applications but never claims an interview exists unless the user confirms it.

Read `references/answer-bank.md` for project-answer structure and `references/revision.md` for role-specific practice.

## Steps

1. **Scope** — collect the target role/JD and the project(s) to prepare. If no role is active, build a general bank for Stride, LoreEngine, StockXpert, and GovBench.
   *Done when:* every answer topic has a named target and approved evidence source.

2. **Build** — prepare concise, truthful answers for problem, user, personal contribution, architecture, failure/debugging, evaluation, trade-offs, 10,000-user limits, and next-month changes.
   *Done when:* all ten prompts are answered or explicitly marked unsupported/unknown.

3. **Revise** — choose the role-relevant fundamentals and create a bounded session plan.
   *Done when:* each revision item has a topic, exercise, and observable completion check.

4. **Mock and debrief** — run a requested mock, grade specificity and truthfulness, then create one improvement action per weak answer. Target three realistic mocks across the sprint.
   *Done when:* the debrief separates knowledge gaps, clarity gaps, and evidence gaps.
