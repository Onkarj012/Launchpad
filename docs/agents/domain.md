# Domain docs

This repository uses a single-context domain-document layout.

Before engineering exploration, read `CONTEXT.md` when it exists and any relevant records under `docs/adr/`. Missing domain files are not errors; continue silently until domain-modeling work creates them.

Use the glossary's exact vocabulary in issues, specifications, test names, and architectural proposals. If a proposal conflicts with an existing ADR, identify that conflict explicitly instead of silently overriding the recorded decision.
