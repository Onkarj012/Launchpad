03 / DECISIONS

Policy stays strict. Proof gets stronger.

No volume target authorizes invented freshness, unsafe eligibility, automatic submission, or legacy fallback.

Freshness

Only Workday DETAIL startDate establishes freshness. LIST-only and genuinely undated roles remain VerifyQueue. Backfill requires known age from 8 to 14 days.

Experience

Missing experience text may pass after full eligibility. Explicit 3+ years fails. Missing eligibility never passes daily selection.

Surfacing

Newly committed Applications v5 row starts cooldown. Planned, failed, recovery-blocked, and no-write rows do not.

Replay

Already committed row creates no duplicate, does not refresh cooldown, and does not increment surfacing count.

User control

Launchpad never changes Make Resume or Applied?. Submission and sending remain manual.

Live scope

Only Normal morning Pune profile gains initial live delivery. Other profiles remain no-write.

05 / DESIGN

One pipeline, one keyed delivery truth.

Complexity stays at source, gateway, and transaction boundaries. Selector and operator flow remain direct.

Canonical selection pipeline

normalize
-> resolve original URL
-> liveness
-> freshness
-> eligibility
-> opportunity-ledger suppression
-> historical suppression
-> readiness
-> scoring
-> selection
-> shortlist limit
-> delivery plan

Selection invariants

selected ∩ VerifyQueue = empty
selected ∩ scoringQueue = empty
selected = planned operations
selected rows have score
selected rows have employer URL

Budget invariants

scorer floor <= downstream reserve
discovery + downstream + handoff
  <= whole-run deadline
source gets start allocation
  or explicit planner omission

Keyed transaction result

{
  status,
  newlyCommitted,
  alreadyCommitted,
  failed,
  recovery,
  deliveredKeys,
}

Status is explicit

noop, replayed, committed, partial, aborted, or recovery.

Commit cardinality

Committed keys must equal verified keys. Missing, duplicate, or unknown key fails closed.

Journal remains evidence

Recovery entries stay visible. No deletion to force retry. Secrets remain redacted.

Delivery order

  1. Build delivery plan.
  2. Stop before gateway factory in no-write mode.
  3. Require completed discovery and scoring.
  4. Construct live gateway lazily and run gateway-owned preflight.
  5. Execute and reconcile keyed transaction.
  6. Record new ledger surfacing and repair missing replay ledger rows from original commit time.
  7. Compute final outcome, evaluate canary, then emit notification receipt.
Success is all-or-truthful

Partial, aborted, recovery, or notification failure degrades run and invalidates success canary. Committed rows remain real. Failed rows remain retryable.

Strict live command

node crawler/cli.mjs daily morning \
  --env production \
  --mode normal \
  --location-preset pune \
  --execute-writes \
  --credential-file ABS_PATH \
  --journal ABS_PATH

Live mode rejects midday, Startup, Remote, non-production environment, arbitrary config, relative paths, orphan secret flags, and incomplete discovery. Partial, failed, and no-write runs call gateway factory zero times.

08 / DAILY USE

Morning work stays human-controlled.

Automation finds, filters, writes, builds, and records. Onkar chooses, reviews, submits, and confirms.

Normal morning

  1. Read notification receipt.
  2. Require completed status and valid canary.
  3. Open Applications v5 by Run ID.
  4. Review shortlist and employer URLs.
  5. Choose roughly 7 to 8 roles when inventory supports it.
  6. Check Make Resume.
  7. Run /make-applications.
  8. Review PDF and live application page.
  9. Submit manually.
  10. Check Applied?.
  11. Run /sync.
  12. Prepare outreach draft only when useful.

Failure handling

Partial discovery

No gateway or success canary. Inspect source manifests. Resume only through supported same-identity recovery.

Partial transaction

Keep committed rows and journal. Failed rows remain retryable. Recovery needs explicit action.

Notification failure

Treat run as degraded. Inspect v5 and local report. Day does not count toward canary streak.

Resume failure

Do not apply. Keep Applied? false. Fix evidence or rendering issue and rebuild.

Dead application page

Do not substitute aggregator URL. Record dead state through supported path and suppress resurfacing.
