Recovery design

Five repair orders. Repair delivery before expanding coverage.

Order A

Durable run control

  • Profile-scoped daily identity
  • Register every planned source before fetching
  • Persist source transitions: pending → running → succeeded / truncated / interrupted / failed
  • Classify stale, over-deadline running rows without deleting history
Order B

One real execution budget

  • createDailyExecution() stays budget owner
  • One parent signal + absolute deadline through every wrapper, adapter, retry, page loop, resolver, detail request, transport call
  • Check remaining budget between boards, pages, retries, queries
  • Outer abort race becomes final guard, not the cancellation mechanism
Order C

Resumable partial handoff

  • Mark active source interrupted, untouched sources not_started
  • Checkpoint run as resumable partial
  • Reconstruct funnel from committed observations; score inside remaining budget
  • Emit versioned result with exact coverage and score state
Order D

Measured source planning

  • Deterministic tiers replace "fetch every board now"
  • 80% measured priority / 20% deterministic exploration until 3 completed runs recalibrate
  • Record why every board was selected, deferred, resumed, omitted
Order E

One pass, one shortlist owner

  • Tracked ATS rotation moves into the durable crawler source plan
  • Remove the second post-crawler fetchWarmAts() pass
  • Mode selector becomes sole owner of scoring, diversity, shortlist, v5 plans
  • Crawler shortlist kept only as compatibility field

Source clearance tiers

Tier 0 · Daily core

Best recurring India/Pune direct ATS coverage. Trusted dates, geography relevance, retained ready-role yield.

Tier 1 · Targeted enterprise

Bounded Workday/enterprise. Relevance, health, continuation cursor, prior ready yield.

Tier 2 · Exploration

Learn new or stale-health boards. Deterministic quota, initially 20% of enterprise budget.

Tier 3 · Opportunistic

Remote, India-startup, SearXNG — only while source budget remains.

Delivery sequence

Six checkpoints, strictly gated. Each must clear before the next begins.

01

Know where work stopped

Stable profile ID, attempt metadata, planned-source rows, explicit source states, stale-run health.
Exit gate
Interrupt after batch 2; same command resumes same ID, no duplicate observations, complete source-state coverage.
Rollback
Restore timestamp default IDs; keep additive telemetry and history.
02

Stop work on time

Signal/deadline propagation, inner-loop budget checks, transport cancellation, cursor checkpointing.
Exit gate
Hanging transport stops within deadline +2s; request count does not rise after cancellation.
Rollback
Disable new deadline path per source; keep parent safety deadline.
03

Return what is usable

Partial checkpoint, durable funnel reconstruction, versioned envelope, score-pending group.
Exit gate
Forced enterprise timeout emits labelled partial output, zero write/surfacing ops; can later complete.
Rollback
Disable partial emission by config; completed/failed paths remain.
04

Spend source time better

Durable ATS rotation, board dedupe, tiered planner, selection reasons, targeted hydration.
Exit gate
No board fetched twice; 3 no-write manifests; source phase ≤12 min, no yield drop.
Rollback
Switch planner to legacy projection; keep lifecycle/cancellation/dedupe telemetry.
05

Produce one answer

Mode selector becomes final authority; unified fetched→dated→eligible→ready→scored→selected telemetry.
Exit gate
Shortlist, v5 plans, receipt counts reconcile; zero-job output names gates or missing coverage.
Rollback
Retain compatibility reserve fields while mode shortlist stays authoritative.
06

Prove it safely

Focused tests, one final full suite, 3 no-write live-local runs, interruption/resume drill.
Exit gate
3 terminal runs ≤20 min, 1 partial→completed resume, no external mutation, nonzero inventory.
Rollback
No production activation; retain previous working config.
Sequential gating: Phase 01 clears before cancellation work starts · Phase 02 proves no adapter leaks before partial delivery · Phase 03 proves partial safety before source prioritization · Phase 04 holds or improves ready-role yield before funnel consolidation · Phase 05 full suite passes once before release work · Phase 06 stops at local proof — commit, push, PR, launchd install, production activation, live smoke, and promotion each need separate explicit authorization.
