Phase detail

Phase 00 — unblock applying

Outcome: one real role reaches a verified one-page PDF and is applied to manually.

  • Commit the resume-contract and identity corrections already in the working tree.
  • Wire the real tailoring pipeline into the resume queue, replacing the injected fixture builder.
  • Build and verify one tailored resume on the new Experience contract, with the Capgemini block frozen.
  • Clear stale status claims in docs/STATUS.md, README.md and the sourcing reference.

Phase 01 — discovery correctness

Outcome: the shortlist is worth the manual effort of applying.

  • Trust a usable Workday DETAIL start date over a relative LIST label.
  • Make provider and requisition identifier the primary durable identity.
  • Propagate every configured resolver limit.
  • Bound scoring by the parent run deadline.
  • Require explicit India or APAC eligibility and apply a real timezone rule.
  • Let the location preset drive board priority instead of only labelling the run.

Phase 02 — skills

Outcome: every skill states when it is done, and the operator stops being the index.

  • Convert the four sequence skills to numbered steps with explicit completion criteria.
  • Define the guardrail vocabulary once and collapse the repeated litany.
  • Add one model-invoked router and reduce each description to a single line.
  • Disclose the two sync branches and settle the mirror question.

Phase 03 — reproducible release

Outcome: a fresh clone of the pushed revision runs and passes every local check.

  • Track the imported career-ops modules.
  • Add a package manifest and lockfile where missing.
  • Derive the fingerprint from the tracked dependency graph.
  • Gate on discovered test inventory and zero failures rather than a fixed count.

Phase 04 — live proof

Outcome: the v5 write path is proven against real credentials, with evidence retained outside the repository.

  • Run a bounded synthetic smoke across Company, Application, Outreach and Activity with reciprocal relations verified.
  • Prove journal reserve, write, read-back and commit, plus an idempotent repeat and an injected abort recovery.
  • Generate the bound Markdown report and JSON sidecar the canary already validates.
  • Notify on every terminal outcome with run identity and a delivery receipt.

Phase 05 — outreach loop

Outcome: a real draft appears, is sent by hand, and the reply closes the loop.

  • Add a Gmail draft-only adapter with an idempotent key, exact attachment and no send capability.
  • Observe replies read-only, match them to the exact Outreach row, and stop the cadence.
  • Keep the initial send timestamp immutable and enforce stage order.

Phase 06 — promotion

Outcome: scheduled runs execute an immutable, rollback-able release.

  • Pin the scheduler to an immutable release checkout and record the rollback revision.
  • Drill lock, journal and corrupted-report recovery.
  • Accumulate seven valid canary days for each profile intended for production.
